# コミュニケーションガイドライン

## 目的
エージェント間および統括部長への報告における情報伝達の質と効率を確保する。

## 適用範囲
全エージェント間のコミュニケーション、および統括部長への報告に適用。

## 基本原則
1. **結論ファースト** - 最初に結論・要旨を述べ、その後に根拠を示す
2. **MECE** - 漏れなくダブりなく情報を整理する
3. **So What** - 単なる事実の羅列ではなく、示唆・提言を添える
4. **数値根拠** - 定量的なデータで裏付ける
5. **読み手目線** - 統括部長の判断に必要な情報を過不足なく提供する

## 報告の構造（ピラミッド構造）
```
結論・要旨
├── 根拠1（データ・事実）
│   ├── 詳細1-1
│   └── 詳細1-2
├── 根拠2（データ・事実）
│   ├── 詳細2-1
│   └── 詳細2-2
└── 推奨アクション
```

## 報告レベル

### Level 1: エグゼクティブサマリー（統括部長向け）
- 1ページ以内
- 結論 → 根拠（3点以内）→ 推奨アクション
- 判断に必要な情報のみ

### Level 2: 詳細報告（部門リード間の共有）
- 3〜5ページ
- 分析の詳細、前提条件、リスク、代替案を含む

### Level 3: 作業レベル（実務担当間の共有）
- ページ数制限なし
- 生データ、計算過程、詳細な分析を含む

## エージェント間連携ルール

### 依頼時のフォーマット
```
【依頼元】部門名 / エージェント名
【依頼先】部門名 / エージェント名
【件名】タスクの概要
【期限】yyyy/mm/dd
【依頼内容】具体的な作業内容
【背景】なぜこの作業が必要か
【期待する成果物】形式・粒度の指定
```

### 回答時のフォーマット
```
【回答者】部門名 / エージェント名
【件名】Re: タスクの概要
【結論】一言で結論
【詳細】分析・調査結果
【留意事項】注意点・前提条件
【次のアクション】推奨する次のステップ
```

## エスカレーション基準
以下の場合は即座に統括部長にエスカレーション:
- 予算超過10%以上の見込み
- 法令違反の可能性
- セキュリティインシデント
- M&A案件のRed Flag
- 部門間で意見が対立し解決困難な場合

## 会議体
| 会議 | 頻度 | 参加者 | 目的 |
|---|---|---|---|
| 経営会議 | 月次 | 全部門リード | 月次業績報告・重要案件協議 |
| 部門連携会議 | 隔週 | 関連部門 | 横断タスクの進捗確認 |
| 緊急対策会議 | 随時 | 関係者 | インシデント・危機対応 |
